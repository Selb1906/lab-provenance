## 진행 기록

### 11-13 C2PA 첫 서명

- 대상: Buildings 2026, 16, 2290 (CC BY, 저자 양현호·김정욱) 13쪽 그림. PDF에서 PyMuPDF로 추출.
- **시행착오 1:** 행동(action)을 `c2pa.published` 하나만 적었더니 서명 거부 — `assertion.action.malformed: first action must be created or opened`. C2PA 규칙상 첫 행동은 "만들었다/열었다"여야 함 → `c2pa.created`(digitalSourceType: digitalCreation) 다음에 `c2pa.published`로 고침.
- **시행착오 2:** PDF에서 뽑은 이미지 중 4.7KB짜리 파일들은 그림이 아니라 같은 그림의 보조 이미지(마스크)였음. 그림 하나가 PDF 안에 두 개의 이미지 객체로 들어 있음.
- **결과:** 검증 상태 `Valid`, 경고 `signingCredential.untrusted`(신뢰 목록에 없는 서명자). 의도한 결과.
- **관찰 — 용량:** 원본 PNG 656,244 B → 서명 후 755,191 B(+98,947 B, +15%). 타임스탬프(TSA)를 빼면 745,136 B → 타임스탬프가 약 10KB, 나머지 약 89KB는 매니페스트·인증서 체인·썸네일. 작은 이미지일수록 증명서 비중이 커진다.
- **관찰 — 콘텐츠 특성:** 논문 그림은 흰 배경 + 선·점이 대부분. 질감이 적어 워터마크를 숨길 자리가 적을 것으로 예상(내 연구의 질감 적응 삽입 원리). 워터마크 비교 때 사진과 따로 본다.

**시행착오**
- c2pa-web 문서가 Context7에 없어서 공식 저장소 README를 직접 읽음. 예전 방식(`createC2pa({settings})`)은 없어졌고 `Reader.fromBlob(c2pa, type, blob, new Context(...))`로 바뀜.
- 번들러 없이 쓰려고 jsDelivr의 `+esm` 묶음을 씀. 워커가 라이브러리 안에서 인라인으로 생성되어 문제없이 동작.
- Python 3.11에서 f-string 안에 역슬래시를 넣어 문법 오류 → 변수로 뺌.
- Playwright MCP는 작업 폴더 밖(E 드라이브)에 스크린샷을 저장하지 못함 → `젠룩\.playwright-mcp`에 저장.

**결과 (Playwright로 로컬에서 확인)**

| 파일 | 판정 | 검증 코드 |
|---|---|---|
| 서명된 그림 | 서명은 유효, 신뢰 목록에 없는 서명자 | `signingCredential.untrusted` |
| 같은 그림 + 연구실 루트를 신뢰 목록에 추가 | **신뢰된 서명자** | 없음 |
| 이미지 라이브러리로 다시 저장 | 증명서 없음 | `no JUMBF data found` |
| 픽셀 데이터 1바이트 변경(증명서는 그대로) | 검증 실패 | `assertion.dataHash.mismatch` |

마지막 두 줄은 구조상 예측대로이며(다시 저장하면 모르는 데이터는 버려지고, 해시는 1비트만 바뀌어도 달라짐) 실험이 아니라 시연으로 둔다. PNG 안에서 증명서는 `caBX` 청크, 픽셀은 `IDAT` 청크에 따로 들어 있다.

- 설치한 MCP: Playwright(`@playwright/mcp@0.0.85`, 브라우저로 사이트를 직접 열어 확인), Context7(`@upstash/context7-mcp@4.6.0`, 라이브러리 최신 문서 조회). 버전 고정 이유: `@latest`면 업데이트마다 재다운로드되어 C 드라이브(여유 3.8GB)를 압박.
- 시행착오:
  1. Windows에서 `npx`를 그대로 MCP로 등록하면 연결 시간 초과 → `cmd /c npx ...`로 감싸서 해결.
  2. Git Bash에서 등록하면 `/c`가 `C:/`로 자동 변환되어 명령이 깨짐 → `MSYS_NO_PATHCONV=1` 설정 후 등록.
  3. Context7은 이전에 받다 만 npx 캐시 때문에 실행 파일을 못 찾음 → 해당 캐시 폴더 삭제 후 재설치.
