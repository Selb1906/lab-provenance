# 11-17 시연 순서 (사이트에서 클릭할 것과 나와야 할 결과)

사이트: https://selb1906.github.io/lab-provenance/ — 모두 브라우저 안에서 처리(파일을 서버로 보내지 않음). 각 결과는 11-15 배포 사이트에서 직접 확인한 것.

## 1. C2PA만으로는 왜 부족한가 (3분)

검증하기 페이지 → 샘플 선택 → "불러오기"

| 순서 | 샘플 | 나와야 할 결과 | 말할 것 |
|---|---|---|---|
| 1 | 논문 그림(아무거나) | "서명은 손상 없이 유효… 신원은 확인하지 못했습니다" + 원장에 같은 파일 | 서명은 유효. 우리 인증서가 공식 신뢰 목록에 없어서 '신원 확인 못 함' |
| 2 | (토글) "연구실 루트 인증서를 신뢰 목록에 넣기" 켜고 다시 | "서명자 확인됨 … (연구실 자체 목록 — C2PA 공식 목록 아님)" | 신뢰는 파일이 아니라 검증하는 쪽이 어떤 루트를 믿느냐로 정해짐 |
| 3 | [변형] 다시 저장한 그림 | "출처 정보가 없습니다" + 원장에서 닮은 그림 찾음(지각 해시 거리 0) | **다시 저장만 해도 C2PA는 사라진다** → 원장·지문이 필요한 이유 |
| 4 | [변형] 픽셀 하나를 바꾼 그림 | "서명 뒤에 파일이 바뀌었습니다" | 반대로 이건 **C2PA만** 잡는다(지문은 같은 그림으로 봄) |

## 2. 그림 말고 다른 형식도 (2분)

| 샘플 | 나와야 할 결과 |
|---|---|
| [변형] 음원을 MP3 32kbps로 다시 압축 | 증명서 없음 + 원장 음원 기록 찾음(음원 지문 BER 약 0.08) |
| [변형] 영상을 좌우 반전해 다시 인코딩 | 증명서 없음 + 원장 영상 찾음(프레임 100% 일치, '좌우 반전된 영상') |
| [변형] 문서 일부(2쪽)만 다시 저장한 PDF | 증명서 없음 + 원장 문서 찾음(5단어 묶음 100%) |
| [다른 형식] 문서(DOCX) | Word 파일 안의 C2PA 서명 유효 |

말할 것: 회사 목표의 네 형식(이미지·영상·음원·문서) 모두 '증명서가 사라져도 원장에서 되찾기'. PDF는 지금 도구로 파일 안에 서명을 못 넣어(sidecar만) 지문 조회가 특히 중요.

## 3. 공격마다 살아남는 층이 다르다 (3분)

출처증명 페이지 → "공격마다 무엇이 살아남나" 표.
- 다시 저장 → fingerprint / 픽셀 하나 → C2PA만 / crop·회전 → 특징점 + 원본에 맞춘 watermark / AI denoiser → watermark는 지워지고 fingerprint가 찾음.
- 표 아래 조건(표본 크기, '원본에 맞추기는 발행자만')을 꼭 같이 말한다.

## 4. 피해자가 몰라도 알려 주기 — 자동 발견 (2분)

자동 발견 페이지 → 가짜 재게시 페이지(블로그·포럼·뉴스·자료실)와 결과 표.
- 근거 등급을 보여 준다: '원장 대조'(내용이 원장과 맞음) vs '워터마크 단서만'(위조될 수 있음).
- ※ 순찰 결과 페이지는 마지막 전체 순찰(11-14) 결과다. 자료실(음원·영상·문서)과 새 근거 등급은 순찰 도구에는 들어갔지만(시험 3/3, 6/6), 메모리 부족 자동 중지로 전체 재실행을 못 해 페이지에는 아직 반영 전 — 시연 전에 재실행할 것.

## 5. 원장과 비트코인 (1분)

출처증명 페이지 아래 → 원장 체크포인트가 비트코인 블록에 들어간 것(최근 78줄 → 블록 975864·975867). "이 기록이 이 시각에 이미 있었다"를 누구나 확인.

## 6. 스스로 찾고 고친 것 (2분) — 발표요약 '시행착오'

watermark key 공개 → 위조 20/20 → 그림별 key(10%) + 원장 대조·정합(0/80) / threshold 15 → 2 / crop 빈틈은 시험 규약 탓 / 클라우드 독립 검토가 내 실험 오류를 찾음(두 번).
