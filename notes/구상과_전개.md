# 구상과 전개 — 과제에서 출발해 어디까지 갔고, 왜 그랬나

이 문서는 결과물이 아니라 **생각의 흐름**을 기록한다. 각 단계가 과제의 어느 문장에서 나왔는지 함께 적어, 확장한 부분도 과제의 연장선임을 보이려 한다. 세부 근거와 수치는 [개발일지](개발일지.md).

## 0. 출발점 — 받은 과제 (2회차, 11-10)

| 과제 문장 | 이 문서에서 부르는 이름 |
|---|---|
| 다음 주까지 웹사이트 같은 것을 만들어 볼 것 | **(가) 웹사이트** |
| C2PA, 핑거프린트, 블록체인, 워터마크, 포렌식을 넣어 볼 것 | **(나) 다섯 기술** |
| 기술보다 도메인을 배우는 것이 핵심. C2PA도 곧 대체될 수 있다 | **(다) 도메인** |
| 한 분야에 자신을 제한하지 말고 풀스택으로. 전공을 잊을 것 | **(라) 풀스택** |
| 완성물보다 성과와 시행착오를 기록해서 보여 줄 것 | **(마) 기록** |
| (1회차) C2PA를 알려면 적용할 콘텐츠의 특성을 알아야 한다 | **(바) 콘텐츠 특성** |

## 1. 첫 구상 — 무엇을 담을 사이트인가 (11-10 ~ 11-13)

- **처음 떠올린 것:** 해 본 적 있는 EMS 대시보드에 C2PA를 붙이는 것. → (라) "전공을 잊을 것"과 (바) "콘텐츠 특성"을 생각하면, 숫자를 보여 주는 대시보드보다 **실제 콘텐츠(그림·문서)를 발행하는 사이트**가 맞다고 판단.
- **정한 것:** 소속 연구실(그린에너지연구소) 홈페이지 + 내 연구 소개. 실제 논문 그림을 콘텐츠로 쓴다.
- **바로 부딪힌 질문 — 무엇을 공개해도 되나?** 논문마다 라이선스가 달랐다(CC BY / CC BY-NC / 학회 저작권 / 게재 예정). 특허 공보에는 발명자 집 주소가 있었다. → 출처증명 이전에 **"어떤 콘텐츠를 어디까지 다시 실을 수 있나"를 판단하는 것 자체가 저작권 도메인 공부**였다. (다)

## 2. 구현하며 생긴 의문 — "C2PA 하나면 되는가?"

- C2PA 서명을 붙여 보니 동작은 했다. 그런데 **다시 저장만 해도 증명서가 통째로 사라졌다.** 1바이트만 바꿔도 "변조"가 됐다.
- 여기서 과제 (나)를 다시 봤다. 다섯 기술을 **나열**하라는 것이 아니라, 왜 다섯 개가 **함께** 있어야 하는지 이해하라는 뜻으로 읽었다. → 이 프로젝트의 **핵심 질문**이 됨: *"왜 C2PA는 다른 기술과 함께여야 의미가 있는가?"*

## 3. 접근 방식에 대한 아이디어 — 하나씩 만들지 말고, 여러 개를 같은 조건에서 비교

- 걱정: 도구를 가져다 붙이기만 하면 "인터넷에 있는 것 가져왔다"는 평가를 받는다.
- 아이디어: 층마다 **알려진 방식 여러 개**를 같은 공격(공개 벤치마크 WAVES)에 노출하고, 무엇이 왜 약한지 **발견**한다. 비교 대상과 공격은 고정하지 않고 해 보면서 넣고 뺀다. 일반 처리(압축·크롭)에 버티는 것만 AI 공격으로 넘긴다.
- 그 과정에서 반복해서 나온 발견: **흰 배경 논문 그림**은 사진과 전혀 다르게 행동했다(워터마크가 안 들어감, 밝기만 올려도 신호가 잘림, 형제 그림끼리 특징이 겹침, ELA가 착시를 만듦). → 1회차의 (바) "콘텐츠 특성을 알아야 한다"를 실험으로 확인한 셈.

## 4. "이게 필요하다"고 판단해 넓힌 것들

| 넓힌 것 | 왜 필요하다고 봤나 | 과제와의 연결 |
|---|---|---|
| **원장(해시체인) + 브라우저 조회** | 워터마크에는 61비트(영문 8글자)밖에 안 들어간다 → 내용이 아니라 식별자만 넣을 수 있고, 그 식별자로 찾아갈 **조회처**가 반드시 필요 | (나) 블록체인을 "왜 필요한가"에서 출발해 구현 |
| **비트코인 시각 고정(OpenTimestamps)** | 연구실 혼자 운영하는 원장은 운영자가 통째로 다시 쓰면 못 막는다 → 외부 증인이 필요 | (나) 블록체인. 회사의 "허가형 폐쇄 해시체인"에 대한 질문으로 이어짐 |
| **조각 단위 핑거프린트** | 실험 결과 논문 그림의 **크롭**이 가장 큰 빈틈(핑거프린트 2~3%, 워터마크 최대 45%) → 발행할 때 조각을 미리 등록하는 방식을 떠올려 60~65%까지 올림 | (나) 핑거프린트 + (바) 콘텐츠 특성 |
| **실제 화면 캡처 실험** | 벤치마크 공격은 인공적이다. 실제로는 "사이트를 열고 캡처"한다 → 실제 브라우저로 재현. 작은 썸네일은 어떤 층으로도 못 찾는다는 결과 → 사이트를 "원본 크기로 보기"로 고침 | (가) 웹사이트를 실제 사용 관점에서 개선 |
| **받는 사람별 워터마크(유출 추적)** | 회사 계획서의 "흔적 표식"이 무엇인지 확인하려고, 포렌식을 '분석'(수동)과 '심기'(능동) 둘 다 해 봄 | (나) 포렌식 |
| **"그림 한 장의 여정" 페이지** | 기술별 결과가 흩어져 있으면 핵심 질문의 답이 안 보인다 → 그림 하나가 겪는 일을 순서대로 보여 주며 "어느 상황에서 누가 답하나"를 한 표로 | (마) 기록을 남이 이해할 수 있는 형태로 |
| **자동 발견(순찰기)** | 멘토 설명에서 C2PA가 규제 대응용이라는 이야기를 듣고, 나도 "그러면 사회적으로 무슨 이점이 있나"를 고민했다. 저작권 분쟁은 피해자가 **알아차려야** 시작된다 → 증명서를 붙이는 것만으로는 부족하고, 내 콘텐츠가 어디서 쓰이는지 **자동으로 알려 주는 순찰**이 있어야 출처증명이 쓸모를 가진다 | (다) 도메인 — 기술이 아니라 "이 기술이 누구에게 어떤 쓸모가 있나"를 고민한 결과 |

## 5. 해 보고 안 된 것, 남긴 것

- **회전:** 어떤 워터마크도 9° 회전을 못 버텼다. 특징점(ORB)만 버틴다.
- **내 연구(블록 DCT)에 크롭 동기화를 붙이는 시도:** 실패. 원인 가설 3가지를 기록하고, 고전 방법(Kutter 자기상관, Pereira-Pun 템플릿)을 조사해 재설계안을 남김.
- **이더리움 테스트넷:** 지갑·테스트 코인 발급에 사람 확인이 필요해 보류.
- **노트북 메모리:** AI 공격 실험이 두 번 강제 종료 → 이미지를 512px로 줄여 완료.

## 7. 한 문장 요약

> 과제의 다섯 기술을 붙여 보다가 C2PA가 혼자서는 금방 사라진다는 것을 확인했고, "그럼 다섯 개가 각각 무엇을 맡아야 하나"를 실험으로 나누어 본 뒤, 마지막에는 "피해자가 알아차리지 못하면 증명서도 소용없다"는 문제의식으로 자동 발견까지 연결했다.
