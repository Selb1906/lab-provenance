## 0. 과제에서 어디까지, 왜 (자세히는 [구상과_전개](구상과_전개.md))

- 과제: 웹사이트 + 다섯 기술(C2PA·핑거프린트·블록체인·워터마크·포렌식), 도메인을 배울 것, 시행착오를 기록할 것.
- 해 보니 C2PA는 다시 저장만 해도 사라짐 → **"왜 다섯 기술이 함께여야 하나"를 핵심 질문으로** 삼음.
- 층마다 여러 방식을 같은 공격으로 비교 → 흰 배경 논문 그림이 사진과 전혀 다르게 행동(1회차 "콘텐츠 특성" 말씀의 실험적 확인).
- 빈틈이 보일 때마다 필요한 것을 덧붙임: 워터마크 8글자 한계 → 원장 / 운영자 재작성 → 비트코인 고정 / 그림 크롭 → 조각 해시 / 실제 캡처 → 썸네일 개선.
- 마지막 질문: 규제 대응용 C2PA가 사회적으로 쓸모 있으려면? → 피해자가 **알아차리게** 해 주는 자동 발견(순찰기).

## 2. 핵심 질문: 왜 C2PA는 다른 기술과 함께여야 하나

**사이트의 '한 장의 여정' 페이지로 시연:** https://selb1906.github.io/lab-provenance/journey.html — 그림 하나를 발행(워터마크+서명+원장) → 메신저 전달 → 크롭 → 화면 캡처 → 내용 조작 → 유출 순으로 실제로 만들고, 단계마다 각 기술의 판정을 보여 줌.

| 일어난 일 | 답하는 기술 |
|---|---|
| 재압축·크롭·캡처로 증명서 삭제 | 워터마크·핑거프린트 → 원장 → 원래 증명서로 복귀 |
| 증명서 남긴 채 내용 조작 | **C2PA만** 탐지(나머지는 '같은 그림'이라고 답함) |
| 유출 | **워터마크(받는 사람별 식별자)만** |
| 원장 조작 | 해시체인 + 비트코인 고정 |


| C2PA의 빈틈 | 메우는 것 | 이번에 확인한 것 |
|---|---|---|
| 다시 저장하면 증명서가 사라짐 | 워터마크·핑거프린트 + 원장 | 증명서 없는 재저장본을 지각 해시로 원장에서 찾아 **원래 증명서 ID로 복귀** |
| 픽셀 하나만 바뀌어도 "변조" | 지각 해시(느슨한 결속) | 엄격한 결속은 "서명 그대로인가", 느슨한 결속은 "원래 기록이 어디 있나"에 답함 |
| 증명서를 둘 곳이 파일뿐 | 원장·블록체인 | 워터마크엔 8글자 ID만 들어감 → 조회처가 반드시 필요 (CAI "Durable Content Credentials"와 같은 구조) |
| 서명 전·기록 없는 파일엔 무력 | 포렌식 | 수동 포렌식은 JPEG 사진 전제, 그림엔 착시. 능동(받는 사람별 ID)은 유출자 추적에 동작 |

## 3. 실험 결과 요약

### 핑거프린트 (이미지 76장, WAVES 공격 8종×5단계, 오탐 1% 기준)
- JPEG 품질 10·잡음·흐림·대비에도 거의 100% 같은 그림을 찾음.
- 9° 회전부터, 크롭은 실제 면적 0.5~0.8에서 거의 못 찾음(시험 규약이 정사각형 크롭이라 가로로 긴 그림은 명목 '10% 크롭'이 실제로는 절반 가까이 잘림). 흰 배경 그림은 회전·지우기의 검은 채움에 사진보다 약함.
- 조각 단위 등록(그림당 해시 126개): 쌍 단위 오탐 기준에선 등록한 비율과 같은 크롭에서 논문 그림 2~3% → 60~65%였으나, **질의 하나를 원장 전체와 비교하는 엄격한 기준(오탐 1%)에선 13~24%** (사진 11~67%). 등록 비율과 다른 크롭에서도 거의 같음 → 빈틈은 일부만 메워짐. imagehash crop_resistant_hash는 그림에서 2%.
- 크롭·회전 보완: PDQ(Meta)도 회전·크롭에 실패. ORB 특징점은 회전 95~100%, 사진 크롭 89~100%로 보완되지만 **논문 그림 크롭은 13~18%**.
  - 이유: 같은 논문의 형제 그림들이 범례·축·도식 부품을 공유해 다른 그림끼리도 특징이 맞음(오탐 문턱이 올라감) + 그림 자체의 특징점이 사진의 1/10.
  - → 논문 그림의 크롭은 핑거프린트만으로는 빈틈.

### 워터마크 (TrustMark, DWT-DCT, DWT-DCT-SVD, 블록 DCT=내 연구 이식)
34장(그림 20, 사진 9, 기타 5), WAVES 8종×5단계. 원본 오탐 0/34(네 방식 모두).

| | 블록 DCT(내 연구) | TrustMark | DWT-DCT 계열 |
|---|---|---|---|
| 강한 곳 | 잡음·밝기·대비·지우기 100%, JPEG 사진 100%(품질 10까지)·그림 70~100% | 사진 크롭 100%(면적 0.6까지), 전반적으로 중간 이상 | 사진 지우기·잡음 |
| 약한 곳 | 흐림, 회전, 크롭 | 회전, **그림 밝기 5%** | **그림엔 아예 안 들어감**, JPEG에 약함(DWT-DCT 0%, SVD는 품질 74에서 89% → 품질 42 이하 33% 이하) |

- 어떤 워터마크도 9° 회전을 못 버팀 → 실험에서 회전을 메운 것은 ORB 특징점뿐(만든 순찰기·원장에는 아직 없음).
- 블록 DCT와 TrustMark는 서로 보완적(신호 처리 vs 크롭).
- 흰 배경 그림: 밝기 ×1.2만으로 배경이 포화되어 TrustMark 신호가 잘림 — DWT-DCT가 그림에 안 들어가는 것과 같은 원리.
- **가장 큰 빈틈: 논문 그림의 크롭**(핑거프린트 13~18%, 워터마크 최대 45%).
- AI 공격(37장, 512px): SD-VAE 재생성은 block DCT를 거의 지우지만 TrustMark가 70~78% 남아 **둘 중 하나는 대부분 남는다**. 반면 FFDNet denoiser는 TrustMark를 0~11%로, block DCT도 그림 26~48%·사진 0~11%로 지워 **이중 삽입으로도 막지 못한다**(10장 때 '정반대로 보완'은 VAE에만 성립). 확산 모델 재생성은 시험 안 함 — 공개 수치로는 TrustMark도 9~34%. → 같은 AI 공격 뒤에도 **fingerprint(perceptual hash + 특징점)는 원본을 95~100% 찾는다**(76장, perceptual hash 단독 92~100%) — watermark가 지워진 자리를 fingerprint와 원장이 메운다. 단, AI 공격 query에서는 perceptual hash 오탐이 원장 75장 기준 3.3%로 늘어남.
- **두 워터마크를 함께 심어도 10장에서 큰 간섭은 보이지 않음**(실험 7, Petrov 등 2025의 1,020장 결과와 같은 방향): 화질 약 3dB 하락(40dB 안팎)으로 JPEG 100%, VAE 재생성 80%, 사진 크롭 100%를 동시에. 남는 빈틈(그림 크롭)은 조각 핑거프린트가 일부만 메움(13~24%).
- 내 방식에 크롭 동기 탐색(반복 반송파 + 접기 상관)을 붙여 봤으나 실패 — 보간 뒤 블록 위상 어긋남, 질감 가중치, 다중 비교가 원인 후보.

### 실제 스크린숏 (사이트를 브라우저로 열어 1920×1080 캡처)
| | 논문 페이지 캡처(그림 315px) | 그림을 탭에서 열어 캡처 |
|---|---|---|
| TrustMark 기본 / 위치 검출 | 0/9 / 1/9 | 0/9 / **8/9** |
| 블록 DCT, 지각 해시 | 0 | 0 |
| ORB 특징점 | 0/18 | **18/18** |
- 작게 보이는 썸네일은 캡처되면 어떤 층으로도 못 찾음 → 발행 설계(원래 크기 보기, 썸네일 별도 서명) 문제.
- TrustMark는 해독 옵션 하나로 0% ↔ 89%.

### 금요일 밤 추가로 알게 된 것
- **원장이 커질 때의 원본 고르기**: Meta의 복제 탐지 모델 SSCD는 단독 판정기로는 약하지만(형제 그림이 비슷한 점수), 상위 5개 후보 안에는 76장 crop·회전 query 760개 모두에서 정답이 들어 있었다 → SSCD 상위 5개 → 특징점 확인 → 정합 후 watermark의 3단계면 원장이 커져도 비교 횟수가 일정.
- **원장이 커지면 '닮음' 판정 문턱을 계속 낮춰야 한다.** 질의 하나를 원장 75장과 비교하면, 쌍 하나 기준으로 정한 문턱(15)에서는 18%가 엉뚱한 그림에 걸린다. 같은 논문의 형제 그림끼리 닮았기 때문. 사이트 원장(그림 10장, 해시 14개)에는 threshold 2를 적용 — 원장이 전부 논문 그림이라 그림끼리 쌍만으로 계산(1,891쌍 중 1쌍 → query FPR 0.74% 점추정, 표본이 작아 상한은 넓음). 대가(그림): brightness 복원 8~61%, JPEG·noise 94~98%, blur·contrast 73~100%.
- **내 워터마크(블록 DCT)는 공개된 사본만으로 위조된다.** 키를 숨겨도 공개 그림 9장의 계수를 평균하면 패턴을 60% 맞게 추정할 수 있고, 이것을 다른 그림 20장에 심으니 20장 모두 '워터마크 있음'(그중 1장은 심기 전부터 threshold 위였음). 한 장만으로도 10~75%(어느 사본이냐에 따라) — 문헌의 copy attack(Kutter 외 2000)과 같은 현상, 여러 장 평균은 Yang 외 2024. 지우기는 어렵다: 추정에 쓴 사본 자신만 두 배 세기(37dB)로 지워졌고 그때 z가 음수로 뒤집힌다. → 워터마크는 '원장을 찾아가는 단서'이지 '진짜임의 증명'이 아니다. 증명은 서명과 원장의 몫.
- **원본에 맞춰 되돌린 뒤 읽으면 크롭·회전도 버틴다.** 발행자는 원본을 갖고 있으므로, **어느 원본인지 알 때**, 의심 이미지를 SIFT로 원본에 registration(오차 0.5px 안팎)해 되돌린 뒤 워터마크를 읽으면 그림 9장에서 block DCT가 서로 다른 크롭 25종 모두, 45°까지 회전 45종 모두 0 → 검출, TrustMark는 회전 45종 모두 0 → 검출(단일 공격, JPEG 없음). "어떤 워터마크도 9° 회전을 못 버틴다"는 원본 없이 읽을 때의 이야기였다. 남은 문제는 '어느 원본인지 고르기'.
- 그림 crop을 못 찾던 큰 이유는 형제 그림보다 **시험 방식**이었다: 표준 시험(WAVES)의 crop은 정사각형으로 잘라 원래 가로세로로 늘리는데, 가로로 긴 그림은 2배 가까이 늘어나 특징점이 안 맞는다. 늘어난 축을 미리 몇 단계 눌러 보고 맞추면 원본 찾기가 3~10% → 66~89%(실제 면적 0.55 미만 crop도 71%), 회전 74~97%. 무관한 이미지 71장을 같은 과정에 넣으면 watermark false positive 0건.
- 이 과정에서 워터마크 키가 공개 저장소 코드에 적혀 있던 것을 발견해 저장소 밖으로 옮기고 다시 발행함.
- **음원(WAV)·영상(MP4)도 같은 서명 코드로 서명·브라우저 검증됨.** 증명서 크기는 약 14KB(그림은 썸네일 때문에 약 100KB).
- 검증 화면 문구를 이용자 연구에 맞춰 바꿈: '없음'은 회색(가짜라는 뜻이 아님), '서명자 확인됨'에는 항상 "내용이 사실이라는 뜻은 아닙니다", 해시 거리 같은 숫자는 '자세히' 안으로.
- 순찰기가 발견할 때 페이지·이미지 해시, 받은 시각, 응답 헤더를 함께 저장하고 그 보고서 해시를 원장에 기록 → 비트코인 시각 고정에 묶임(분쟁 증거의 동일성·무결성 요건).

## 4. 시행착오 (일부)

- C2PA 첫 행동을 "발행"으로만 적어 서명 거부 → 규칙상 "만들기/열기"가 먼저.
- TrustMark에 14글자를 넣었다가 8글자로 잘림 → 워터마크엔 ID만, 내용은 원장에.
- 핑거프린트 문턱을 그룹별로 정했다가 표본 수 차이로 불공정 → 공통 문턱으로 다시 계산.
- 브라우저와 Python이 같은 지각 해시를 내야 조회가 됨 → 해시 규격을 직접 정함(업계가 PDQ 같은 규격을 두는 이유).
- Windows에서 OpenTimestamps 클라이언트 실행 불가 → 라이브러리로 캘린더 서버에 직접 요청.
- 비트코인 확정 확인 코드가 3시간 동안 "대기"만 출력 → 실제로는 내 코드가 매번 실패하고 있었음(예외를 삼킴). 고친 뒤 확정 확인. "아무 일 없음" 출력이 실패를 숨길 수 있다.
- PNG 그림에 ELA를 써 보니 붙인 조각이 4배 밝게 보였지만 압축 이력이 아니라 질감 차이 때문 → 흰 배경 그림에서 ELA는 착시.

## 5. 회사에 확인하고 싶은 것

1. "C2PA를 90% 뚫리지 않게"의 %는 어떤 지표인가 — 변형 후 출처 복원율? 어떤 변형 기준?
2. 5단계 중 "숨은 도장"과 "흔적 표식"의 차이 — 모두에게 같은 ID(출처 복원) vs 받는 사람별 ID(유출 추적)인가?
3. "허가형 폐쇄 해시체인"에 젠룩 말고 누가 노드로 참여하나? 운영자가 한 곳뿐이면 원장 전체 재작성을 못 막는데, 외부 고정(비트코인 등)이나 다른 기관 서명으로 보완하나?
4. 논문 그림·도면처럼 흰 배경이 많은 콘텐츠에서 워터마크를 어떻게 처리하나?
5. 젠룩의 워터마크도 키(또는 모델)가 하나로 고정돼 있다면, 공개된 사본 여러 장만으로 위조할 수 있는지 시험해 봤나?
6. C2PA 적합성 심사는 어디까지 진행됐고 걸림돌은 무엇인가? (적합성 프로그램은 신청·등재 비용이 없고 회원이 아니어도 되며, 등재까지 중앙값 16일. 국내 5개사 9건은 모두 2026-06~10에 보증 등급 1로 등재)
7. 계획서의 "C2PA 시장 12억→87억 달러" 수치의 출처는? (조사로는 원출처를 못 찾았고, 같은 이름의 보고서끼리 3배 넘게 차이) 워터마킹 수치는 'AI 워터마킹' 시장 보고서의 값으로 보이는데 맞나?
8. 웹에서 사본을 찾아 주는 순찰(자동 발견)은 계획에 있나? 해외 업체(IMATAG 등)는 이것을 판매하고, 포털의 검사 항목에는 없다.
