# 2회차 과제 중간 보고 (11-17 화)

연구실 홈페이지에 C2PA·핑거프린트·블록체인·워터마크·포렌식을 붙여 본 결과와 시행착오.
사이트: https://selb1906.github.io/lab-provenance/ · 소스와 전체 일지: https://github.com/Selb1906/lab-provenance

## 1. 무엇을 만들었나

- 그린에너지연구소 + 내 연구 소개 사이트. 오픈액세스 논문 그림 9장을 발행할 때 C2PA로 서명.
- 검증 페이지: 방문자가 올린 파일을 **브라우저 안에서** 검증(서버로 보내지 않음).
  - C2PA 판정 + 원장 조회(파일 해시·지각 해시)를 함께 보여 줌.
  - "연구실 루트를 신뢰 목록에 넣기" 토글로 같은 파일이 '신뢰 안 됨' ↔ '신뢰됨'으로 바뀌는 것을 시연.
- 공개 원장(해시체인) + 원장 끝 해시를 OpenTimestamps로 비트코인에 고정.

## 2. 핵심 질문: 왜 C2PA는 다른 기술과 함께여야 하나

| C2PA의 빈틈 | 메우는 것 | 이번에 확인한 것 |
|---|---|---|
| 다시 저장하면 증명서가 사라짐 | 워터마크·핑거프린트 + 원장 | 증명서 없는 재저장본을 지각 해시로 원장에서 찾아 **원래 증명서 ID로 복귀** |
| 1바이트만 바뀌어도 "변조" | 지각 해시(느슨한 결속) | 엄격한 결속은 "서명 그대로인가", 느슨한 결속은 "원래 기록이 어디 있나"에 답함 |
| 증명서를 둘 곳이 파일뿐 | 원장·블록체인 | 워터마크엔 8글자 ID만 들어감 → 조회처가 반드시 필요 (CAI "Durable Content Credentials"와 같은 구조) |
| 서명 전·기록 없는 파일엔 무력 | 포렌식 | 수동 포렌식은 JPEG 사진 전제, 그림엔 착시. 능동(받는 사람별 ID)은 유출자 추적에 동작 |

## 3. 실험 결과 요약

### 핑거프린트 (이미지 76장, WAVES 공격 8종×5단계, 오탐 1% 기준)

- 9° 회전, 10% 크롭부터 거의 못 찾음. 흰 배경 그림은 회전·지우기의 검은 채움에 사진보다 약함.

## 4. 시행착오 (일부)

- C2PA 첫 행동을 "발행"으로만 적어 서명 거부 → 규칙상 "만들기/열기"가 먼저.
- TrustMark에 14글자를 넣었다가 8글자로 잘림 → 워터마크엔 ID만, 내용은 원장에.
- 핑거프린트 문턱을 그룹별로 정했다가 표본 수 차이로 불공정 → 공통 문턱으로 다시 계산.
- 브라우저와 Python이 같은 지각 해시를 내야 조회가 됨 → 해시 규격을 직접 정함(업계가 PDQ 같은 규격을 두는 이유).
- Windows에서 OpenTimestamps 클라이언트 실행 불가 → 라이브러리로 캘린더 서버에 직접 요청.
