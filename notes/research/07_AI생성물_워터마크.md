## 5줄 요약
1. **생성 과정 워터마크**(Stable Signature·Tree-Ring·Gaussian Shading·PRC)는 생성 모델을 가진 쪽만 심을 수 있어 연구실 그림엔 적용 불가하고, 검출에 같은 확산 모델과 DDIM 역변환이 필요하다. 구글 SynthID-Image는 100억 장 이상 적용됐지만 비공개이며, 논문 본문상 구조는 TrustMark와 같은 **생성 후 부호기·복호기 방식**이다.
2. 공격 문헌은 우리 관찰을 대체로 설명한다: 작은 섭동 워터마크는 재생성에 "증명 가능하게" 지워지고(Zhao 외 2023 정리 4.3), 재생성·편집은 중·고주파 패턴을 제거한다(VINE: DWTDCT 0.09%) → 블록 DCT 0%. 학습형은 압축형 재생성을 견딘다(WAVES StegaStamp Regen-VAE 1.000) → TrustMark 80%는 **잡음 없는 약한 재생성에서의 값**이며 강한 재생성에선 TrustMark도 9~34%(VINE).
3. 상충도 있다: Liang 외 2025는 디노이저형 공격이 TrustMark엔 약하고 DCT형엔 강하다고 보고(우리와 반대 순서). FFDNet σ=25를 TrustMark에 적용한 문헌 수치는 없어 우리 결과는 새 데이터 포인트이되 공격 세기 차이를 함께 적어야 한다. 9° 회전 0%는 WAVES·TrustMark 학습 설정과 일치.
4. **새 위험**: 블록 DCT는 키에서만 나오는 고정 패턴(content-agnostic)이라 Yang 외 2024의 평균화 공격(DwtDctSvd 1.000→0.317, Tree-Ring 위조 100%)에 노출될 수 있다. 사이트에 같은 키로 9장을 발행한 상태.
5. **화요일까지 추천**: ① 평균화 공격으로 블록 DCT 패턴 노출·위조 시험(numpy, 1시간), ② Watermark Anything(MIT, 378MB, 국소화 32비트)로 그림 크롭 빈틈 시험(2~3시간; 대안 Video Seal 이미지 모델), ③ CompressAI bmshj2018 재생성 + FFDNet 반복 + 잠재 잡음(1~2시간, Windows 설치 위험). 음원(AudioSeal)·텍스트(SynthID Text)는 보류.

## 1. 생성 과정에 심는 워터마크 vs 생성 후 심는 워터마크

용어. **생성 과정 워터마크**(in-generation / in-model watermark) = 생성 모델이 그림을 만드는 도중에 표식을 심는 방식. 모델을 가진 쪽(구글·Meta·Stability 등)만 심을 수 있고, 이미 있는 그림(사람이 그린 논문 그림)에는 못 쓴다. **생성 후 워터마크**(post-hoc watermark) = 완성된 픽셀에 따로 표식을 더하는 방식. 우리 TrustMark·블록 DCT가 여기 속한다. **잠재 공간**(latent) = 확산 모델이 그림 대신 다루는 작은 압축 표현(Stable Diffusion은 512×512 그림을 4×64×64로 줄임). **DDIM 역변환**(inversion) = 완성 그림에서 처음 잡음을 거꾸로 추정하는 계산(생성과 비슷한 비용, 보통 50단계).

### 1.2 Google SynthID(이미지)

- 논문: Gowal 외(저자 26명), "SynthID-Image: Image watermarking at internet scale", arXiv:2510.09263(2025-10, 프리프린트). 구글 서비스에서 **100억 장 이상**의 이미지·영상 프레임에 적용(초록). 검증 서비스는 "신뢰 테스터"에게만, 외부용 변형 **SynthID-O**는 파트너십으로 제공. **코드·가중치 비공개, 모델 크기 비공개.**
- 구조: 2023 블로그는 "픽셀에 직접", 워터마커·검출기 두 신경망 공동 학습, 3단계 판정(있음/없음/있을 수 있음). 논문 본문(1·2.2·2.3절)은 **생성된 픽셀에 부호기 신경망으로 표식을 더하고 복호기가 검출 로짓과 페이로드 비트를 내는 구조**로 기술한다(이 조사에서 HTML 본문 기준으로 확인; 초록에는 명시 없음). 즉 구글 생성 파이프라인 **안에서** 돌지만 구조상으로는 TrustMark와 같은 **생성 후(부호기·복호기) 방식**이다 — "생성 과정 워터마크"라는 통념과 다른 점.
- 용량·수치(본문 8절): SynthID-O는 512×512에서 **136비트**. TPR@0.1%FPR(변환 30종·6군, 최악 경우로 문턱 보정, 표 1): 무작위 변환 종합 99.98%, 최악 종합 99.72%, 최악 조합 98.06%(차순위 대비 +9.36/+16.35pp); 페이로드 비트 정확도(표 3) 99.59%/98.07%. 변환별 세부(JPEG·크롭) 표는 본문에 없음.
- 검출 포털 "SynthID Detector": 2025-05-20 발표(이미지·음원·영상·텍스트, 언론·연구자 대기열), 2026-10 일반 공개는 2차 보도만 확인. 텍스트만 오픈소스(2절).

### 1.4 두 부류의 차이(정리)

| 관점 | 생성 과정(Stable Signature·Tree-Ring·Gaussian Shading·PRC) | 생성 후(TrustMark·StegaStamp·Watermark Anything·Video Seal·SynthID) |
|---|---|---|
| 누가 심나 | 생성 모델을 돌리는 쪽만 | 누구나, 어떤 그림에나(사람이 그린 논문 그림 포함) |
| 기존 그림 | 불가(ZoDiac만 예외, GPU 45~256초/장) | 가능 |
| 검출에 필요한 것 | 잠재형(Tree-Ring·GS·PRC·WIND·ZoDiac): **같은 확산 모델 + DDIM 역변환 50~100단계**(GPU급). Stable Signature는 소형 추출기만 | 소형 추출기 CNN(TrustMark ResNet-50 256×256, CPU 가능) |
| 재생성 공격 | 잠재형이 강함: ZoDiac SD 재생성 60단계 0.988, PRC "TPR 0.99 미만으로 떨어진 공격 없음"; 단 WAVES에서는 Tree-Ring도 Regen-Diff 0.258~0.612, Rinse-4x 0.110(3절). **Stable Signature는 거의 전멸(WAVES 0.000)** | 작은 섭동 방식은 제거됨(Zhao 정리 4.3); StegaStamp(PSNR 28.5, 큰 섭동)만 버팀 |
| 화질·탐지 불가성 | GS·PRC는 분포 동일(FID t값 0.36 vs Tree-Ring 2.58, GS 논문); Stable Signature PSNR 30 | PSNR 38~50dB, 잔차가 측정됨 |
| 다중 키·식별 | Tree-Ring 키 2048개에서 0.20(깨끗)→RingID 0.819, WIND 0.969 | 비트 수만큼(TrustMark 61비트, PRC는 생성형 512비트) |
| 우리 과제와의 관계 | 연구실 그림(사람이 만든 것)에는 **적용 불가**. 젠룩의 "AI 생성물 표시" 맥락에서는 생성 서비스 제공자 측 기술 | 우리가 쓰는 부류. 생성 후 방식 중 재생성에 강한 것은 큰 섭동(StegaStamp) 또는 저주파·생성 사전 활용(VINE, 3.5절) |

## 2. 음원·영상·텍스트·방송 워터마크

용어: **국소화 워터마크**(localized watermark) = "이 파일 전체에 있다/없다"가 아니라 "몇 초부터 몇 초까지(또는 어느 영역에) 있다"를 샘플·픽셀 단위로 찍어 주는 방식. 편집으로 일부만 AI 생성물이 섞인 경우에 필요하다.

## 3. 공격과 벤치마크(2023~2026)

용어: **재생성 공격**(regeneration attack) = 그림에 잡음을 섞은 뒤 압축기·디노이저·생성 모델로 "그럴듯한 그림"을 다시 만들어 내는 공격. 원래 그림과 내용은 같지만 픽셀은 새로 그려지므로, 픽셀에 얹힌 워터마크가 사라진다. **적대적 임베딩 공격**(adversarial embedding attack) = 공개된 신경망(예: CLIP, VAE 부호기)이 뽑는 특징 벡터가 바뀌도록 눈에 안 띄는 잡음을 최적화해 더하는 공격. **위조**(spoofing/forgery) = 워터마크가 없는 그림을 "워터마크 있음"으로 판정되게 만드는 공격(출처를 뒤집어씀).

### 3.1 재생성 공격 — Zhao 외, "Invisible Image Watermarks Are Provably Removable Using Generative AI" (2023, NeurIPS 2024, arXiv:2306.01953)

- **무엇을**: 잡음 추가 → 복원(디노이저, 학습된 압축 VAE, Stable Diffusion) 두 단계로 워터마크를 지운다. **왜 중요한가**: 정리 4.3에서 "ℓ2 거리로 Δ만큼만 바꾼(Δ-invisible) 워터마크"는 잡음 크기 σ가 LΔ(L은 복원기의 국소 Lipschitz 상수)보다 충분히 크면 어떤 검출기도 제2종 오류(놓침)가 Φ(Φ⁻¹(1−ε₁) − LΔ/σ) 아래로 내려갈 수 없다고 **증명**한다. 즉 "눈에 안 띄게 작게 얹은 워터마크는 그만큼의 잡음으로 반드시 지워진다"(출처: 본문 4절, 정리 4.3; 실험 확인은 L=1, σ=1.16Δ, 그림 2).
- 시험 대상 4종(픽셀 수준): DwtDctSvd(PSNR 39.38), RivaGAN(40.55), SSL(41.79), StegaStamp(28.50) — 공격 전 TPR@FPR1% 모두 1.000(표 1, MS-COCO).
- 공격 설정: CompressAI의 VAE Bmshj2018·Cheng2020(압축 품질 1~6), Stable Diffusion v2.1 잡음 10~200단계(σ 0.10~0.57, PNDM 샘플러).
- 결과: DwtDctSvd·RivaGAN·SSL은 VAE·확산 공격 모두에서 "99% 이상" 제거(본문), RivaGAN은 PSNR 30 이상을 유지하며 98% 제거(서론). **StegaStamp는 큰 잡음의 확산 공격에서만 제거**(본문; 정확한 값은 그림 4·7에만 있어 수치 확인 못 함).
- **Tree-Ring(생성 과정에 심는 의미 워터마크)은 모든 공격을 버팀**: TPR@FPR1% — VAE-Bmshj2018-3 0.998, VAE-Cheng2020-3 1.000, 확산 60단계 1.000(MS-COCO, 부록 E.1 표 2). 대가: 원본과 픽셀·잠재 공간 거리가 훨씬 큼(그림 14, "강건함은 공짜가 아니다").
- 코드: https://github.com/XuandongZhao/WatermarkAttacker (라이선스는 5절 참조).

### 3.2 공격의 이론적 한계와 위조 — Saberi 외, "Robustness of AI-Image Detectors: Fundamental Limits and Practical Attacks" (arXiv:2310.00076, 2023/2024; 학회 표기는 arXiv 페이지에 없어 확인 못 함)

- **작은 섭동 워터마크**(눈에 안 띄게 조금 바꾼 것)는 **확산 정화**(diffusion purification: 잡음 추가 후 확산 모델로 복원)로 제거되며, 회피 오류(워터마크를 놓침)와 위조 오류(없는 걸 있다고 함) 사이에 근본적 트레이드오프가 있음(초록).
- **큰 섭동 워터마크**(StegaStamp처럼 PSNR이 낮은 것)는 정화로는 안 지워지고, **모델 대체 적대적 공격**(공개 모델로 대리 검출기를 만들어 공격)으로 지운다(초록).
- **위조 공격**: 워터마크 API를 블랙박스로만 써도 "워터마크가 들어간 잡음 그림"을 만들어 실제 사진에 더하면 실제 사진이 워터마크 있음으로 판정됨(초록). → 젠룩의 '표시 의무' 맥락에서는 "AI 생성물에 워터마크가 있다"뿐 아니라 "사람이 만든 것에 가짜 AI 워터마크를 씌울 수 있다"는 뜻.

### 3.3 WAVES 벤치마크 — An 외, "WAVES: Benchmarking the Robustness of Image Watermarks" (ICML 2024, arXiv:2401.08573)

- 대상 3종: Tree-Ring(생성 과정), Stable Signature(생성 과정, 복호기 미세조정), StegaStamp(생성 후). 데이터 DiffusionDB·MS-COCO·DALL·E3 각 5,000장(부록 D.1).
- 왜곡 8종 × 5단계(부록 F.1; 우리 실험 2가 따른 설정): 회전 9°~45°, 크롭 면적 10~50%, 지우기 5~25%, 밝기 +20~+100%, 대비 +20~+100%, 가우시안 흐림 커널 4~20px, 가우시안 잡음 표준편차 0.02~0.1([0,1] 척도), JPEG 품질 90~10. **우리의 "9° 회전"은 WAVES의 가장 약한 회전 단계**다.
- 재생성 공격(부록 F.2): Stable Diffusion v1.4 40~200단계, VAE(bmshj2018) 품질 1~7, KL-VAE 병목 4/8/16/32, 2회·4회 반복("rinsing").
- 적대적 공격: 임베딩 공격(PGD, ResNet18·CLIP·KL-VAE16·SDXL-VAE 블랙박스, KL-VAE8 그레이박스, 세기 2/255~8/255) 및 대리 분류기 공격.
- 핵심 수치(공격 세기 5단계 평균 TPR@0.1%FPR = "Avg P"). 논문 HTML의 표 3(검출)과 표 6(식별, 사용자 100만 명)이 값이 다르므로 둘을 함께 적는다(표 3 / 표 6): **Stable Signature — Regen-Diff 0.001 / 0.000**(거의 전멸), Regen-KLVAE — / 0.047, 적대적 공격에는 0.998~1.000; **StegaStamp — Regen-Diff 0.943 / 0.766**, Regen-VAE — / 1.000, Regen-KLVAE — / 0.999(압축형 VAE 재생성에는 거의 영향 없음), 적대적 공격 1.000; **Tree-Ring — Regen-Diff 0.612 / 0.258, Rinse-4xDiff 0.443 / 0.110, 그레이박스 임베딩 공격(KL-VAE8) 0.448 / 0.259**("TPR이 거의 0까지 떨어질 수 있다", 그림 4), 대리 분류기 공격 0.49~0.50 / 0.34~0.35. 회전(표 6): Tree-Ring 0.131, Stable Signature 0.400, StegaStamp 0.288 — 셋 다 크게 무너짐.
- 본문 문장: "Stable Signature는 거의 모든 재생성 공격에 취약", "Tree-Ring은 재생성 공격에 강건하지 않다"(Zhao 외 2023의 결론과 반대 — 공격 세기 차이), "StegaStamp는 재생성에 약간만 영향, 그것도 확산 공격에만", "세 워터마크 모두 왜곡에는 상대적으로 강건".
- 코드·모델: https://github.com/umd-huang-lab/WAVES (MIT), 리더보드 https://wavesbench.github.io/
- 결론 문장: "어떤 단일 공격도 모든 워터마크에 두루 뛰어나지 않다"(4.2절) — 우리 실험 2·7의 "서로 보완" 결론과 같은 구도.

### 3.4 평균화(스테가분석) 공격 — Yang 외, "Steganalysis on Digital Watermarking: Is Your Defense Truly Impervious?" (arXiv:2406.09026, 2024; 학회 확인 못 함)

- **무엇을**: 워터마크 있는 그림 n장과 없는 그림 n장을 각각 평균해 빼면(δ̂ = 평균(x_w) − 평균(x_∅)) **내용과 무관하게 같은 패턴을 심는(content-agnostic) 워터마크**의 패턴이 드러나고, 이를 빼서 제거하거나 깨끗한 그림에 더해 **위조**한다. 그레이박스는 짝지은 원본, 블랙박스는 무관한 ImageNet 그림을 쓴다. n=5~5000.
- 수치(n=5000, 블랙박스/그레이박스): Tree-Ring AUC 1.000→0.241/0.259(그레이박스 **n=5에서 이미 0.141**); Gaussian Shading 비트 정확도 0.999→0.462; DwtDctSvd 1.000→0.572/0.317; 반면 **내용 적응형**인 Stable Signature 0.998→0.998, DwtDct 1.000→0.998(변화 없음). Tree-Ring **위조**: 깨끗한 그림에 추정 패턴을 더하면 n=5~5000 모두에서 검출기를 완전히 속임(표 1, "completely deceive"). 그레이박스는 50장 이상, 블랙박스는 약 100장이면 눈에 띄는 흔적이 거의 없음(본문). 코드 공개 확인 못 함.
- 지침: "스테가분석을 버티려면 내용 적응형 워터마크를 쓰라", 다중 키는 임시 완화일 뿐(3개 키 혼합 시 AUC 0.2→0.7, 부록 A.6).
- **우리 블록 DCT에 직접 해당**: 같은 키의 고정 의사난수 패턴을 모든 그림에 심으므로 분류상 content-agnostic에 가깝다(질감 적응 세기는 있음). 사이트에 같은 키로 9장을 발행했으므로 공격자가 n=9를 바로 확보한다. **단일 키의 패턴 노출 위험은 우리가 아직 시험하지 않은 공격**(4·6절).

## 4. 우리 관찰을 설명하는 이론·실험

우리 관찰(실험 2·7, 512px, 그림 5·사진 5): ① FFDNet σ=25 디노이저 → TrustMark 0.00/0.00, 블록 DCT 0.60/0.20. ② SD-VAE(`sd-vae-ft-mse`) 한 번 통과 → 블록 DCT 0.00/0.00, TrustMark 0.80/0.80. ③ 9° 회전 → 네 방식 모두 0.

### 4.1 "작게 얹은 워터마크는 재생성에 지워진다" — 블록 DCT 0%를 설명(사실)
- **Zhao 외 2023 정리 4.3**(3.1절): ℓ2 거리 Δ만큼만 바꾼 워터마크는 잡음 σ≳LΔ로 복원하면 어떤 검출기도 놓침 확률이 Φ(Φ⁻¹(1−ε₁)−LΔ/σ) 아래로 못 내려간다. 단 **VAE 공격은 이 정리에 직접 포함되지 않음**(비고 C.6) — VAE 재생성에 대한 설명은 실험적이다.
- **Saberi 외 정리 1**: 확산 정화 후 회피 오류+위조 오류 ≥ 1−erf(√ᾱ_t·W/(2√(2(1−ᾱ_t)))), W는 워터마크 유무 분포의 ℓ2 Wasserstein 거리. 표 1 평균 ℓ2 거리: RivaGAN 4.19, DwtDct 5.59, DwtDctSvd 5.54, StegaStamp 17.40, Tree-Ring 117.58. 작은 W(우리 블록 DCT PSNR 41~43, TrustMark 43~45 모두 "작은 섭동" 부류)일수록 제거가 쉽다는 이론.
- **주파수 관점 — VINE(Lu 외, ICLR 2025)**: "이미지 편집(재생성)은 **중·고주파 대역의 패턴을 주로 제거**하고 저주파는 덜 영향"(1절·3.1절), "흐림 왜곡이 비슷한 주파수 특성을 가져 학습 시 대리 공격으로 쓸 수 있다"(초록), 부록 B: 편집에 대한 강건성은 "워터마크 에너지가 저주파에 집중될수록" 높다. 표 1: **DWTDCT 재생성 후 TPR 0.09%/0.00%**, DWTDCTSVD 3.12%/1.43%. 우리 블록 DCT는 8×8 블록의 AC 계수 63개 전부(고주파 포함)에 alpha/√63씩 분산 → 바로 이 "중·고주파에 얹은 패턴"이다. **일지의 추정("63개 계수 전부에 분산한 설계의 대가")을 문헌이 뒷받침.**
- 고전 설명: 확산 스펙트럼 검출은 선형 상관(Cox 외 1997)이고, 재생성은 비선형 재구성이므로 상관이 깨진다. Voloshynovskiy 외, "Attacks on Digital Watermarks: Classification, Estimation-Based Attacks, and Benchmarks", IEEE Communications Magazine 39(8), 2001, DOI 10.1109/35.940053 — "추정 기반 공격"(원본 추정=디노이징 → 워터마크 추정·제거) 체계화. 디노이저와 VAE 모두 이 틀의 "원본 추정기"다.

### 4.2 "학습형은 압축형 재생성에 버틴다" — TrustMark 80%를 설명(사실+추정)
- WAVES 표 6: **StegaStamp는 Regen-VAE 1.000, Regen-KLVAE 0.999**(압축형·오토인코더형 재생성에 거의 무손실), 확산 재생성에만 0.766. Zhao 외: StegaStamp는 "큰 잡음의 확산 공격에서만 제거". 즉 **학습형(왜곡 층을 넣어 학습한 부호기·복호기)은 오토인코더 한 번 통과를 "학습에서 본 왜곡"처럼 견딘다**.
- 우리 SD-VAE 공격은 KL-VAE(f=8) 한 번 통과이고 **잡음을 더하지 않았다** — WAVES Regen-KLVAE·Zhao의 VAE 공격 중 가장 약한 쪽에 해당(추정). TrustMark가 80% 버틴 것은 이와 일관된다.
- 반면 **잡음을 더한(확률적) 재생성**에서는 TrustMark도 무너진다: VINE 표 1 **TrustMark 9.22%(확률적)/34.20%(결정적 역변환)**; Fu 외 2025(arXiv:2511.05598)는 TrustMark·StegaStamp·VINE 모두 복호 정확도를 거의 0으로(초록). → **우리 80%는 "약한 재생성"에서의 값이며, SD 재생성에 잡음 단계를 추가하면 떨어질 것**(추정, 6절 추천 공격으로 확인 가능).

### 4.3 "학습형은 디노이저에 약하다" — TrustMark 0%는 문헌과 **부분적으로 상충**(사실)
- 뒷받침: MarkSweep(arXiv:2602.15364, 2026; 2차 요약만 확인)은 "잔차 잡음의 크기가 매우 작다"는 전제에서 고주파 영역의 워터마크 잡음을 증폭한 뒤 주파수 인식 디노이저로 지워 HiDDeN·Stable Signature 비트 정확도를 우연 수준으로 떨어뜨린다고 보고. Qi 외(arXiv:2603.12949, 2026; 검색 요약만)는 확산 편집이 "데이터 의존 디노이징 필터처럼 작동해 부자연스러운 고주파 성분을 억제"한다고 기술.
- **상충**: Liang·Li·Sun, "A Baseline Method for Removing Invisible Image Watermarks using Deep Image Prior", arXiv:2502.13998(2025): 주파수 분석에서 "RoSteALS·StegaStamp는 저·중주파, DwtDctSVD·SSL은 중·고주파, RivaGAN은 고주파"에 영향을 주고 **"TrustMark만 스펙트럼에서 패턴이 잘 안 보인다"**; 디노이저형 공격(Deep Image Prior)은 **DwtDctSVD·RivaGAN에 가장 효과적**이고 **TrustMark·RoSteALS·StegaStamp에는 제한적**, 이들은 DiffPure(잡음+확산)로만 지워진다. 즉 이 논문의 순서(디노이저는 DCT형을 더 잘 지움)는 **우리 순서와 반대**.
- 해석(추정): 공격 세기 차이. FFDNet σ=25는 조기 종료 DIP보다 훨씬 강한 디노이저이고, 우리 블록 DCT는 질감 적응 때문에 **질감 블록에 신호가 몰려** 있어 디노이저가 보존하는 세부와 함께 일부 살아남는다(0.2~0.6). TrustMark의 잔차는 256×256에서 계산해 업샘플한 저진폭 패턴(논문 알고리즘 1)인데, σ=25 수준 디노이징은 그 진폭대를 통째로 지우는 것으로 보인다. **FFDNet(또는 DnCNN) σ=25를 TrustMark에 적용한 문헌 수치는 찾지 못했다** → 우리 결과는 새로운 데이터 포인트이되, Liang 외와의 상충을 함께 적어야 한다.

### 4.4 회전 0% — 문헌과 일치(사실)
- WAVES(표 6, 회전 9~45° 평균): Tree-Ring 0.131, Stable Signature 0.400, StegaStamp 0.288. 우리 9°는 WAVES 최약 단계인데도 0인 이유: TrustMark 학습 변환에 **회전이 없음**(논문; 뒤집기·크롭·리사이즈만), invisible-watermark README도 "30° 회전 실패". 블록 DCT는 격자 동기가 깨지면 상관이 0이 되는 고전적 약점(일지 기록과 같음).
- 회전에 강한 설계는 **처음 잡음의 푸리에 고리**(Tree-Ring 회전 75° AUC 0.935 — 고리는 회전해도 고리)지만 생성 과정 전용이고, 기존 그림용 ZoDiac은 회전 0.538이다. 생성 후 방식에서 회전은 여전히 동기화(조사 03) 문제다.

## 6. 종합 추천(화요일 11-17까지 노트북 CPU로 추가할 것)

전제: 노트북 CPU, 이전에 SD-VAE 로드 시 메모리 부족으로 중단된 이력(일지), 표본 10장(512px) 기준 실험 2·7과 비교 가능해야 함. 우선순위는 "실행 비용 대비 발표에서 말할 수 있는 것"으로 매겼다.

### 1위 — 공격 추가: **평균화(스테가분석) 공격**으로 블록 DCT의 고정 패턴 노출·위조 시험
- **무엇을**: 우리 블록 DCT는 `_carrier(key, …)`가 키에서만 생성되는 의사난수 패턴(질감 적응 세기만 그림에 따라 변함)이므로 Yang 외 2024의 "content-agnostic" 부류다. (a) 그레이박스: 실험 2의 워터마크 그림 n장과 원본 n장의 차를 평균해 패턴 추정 → 빼서 z 점수 변화, 깨끗한 그림에 더해 위조 z 점수. (b) 블랙박스: 원본 없이 워터마크 그림 평균 − 무관한 그림 평균. n=5, 10, 34(실험 2 전체 표본) 세 단계. TrustMark에도 같은 절차를 적용해 "내용 적응형은 안 뚫린다"를 대조.
- **왜(근거)**: Yang 외 2024(arXiv:2406.09026) — content-agnostic DwtDctSvd 비트 정확도 1.000→0.317(그레이박스 n=5000, 표 4), Tree-Ring은 그레이박스 n=5에서 AUC 0.141(표 2), 위조 100% 성공(표 1); 내용 적응형 Stable Signature·DwtDct는 변화 없음(표 7·11). 지침 "내용 적응형을 쓰라". 우리 사이트는 같은 키로 9장을 발행했으므로 공격자가 n=9를 즉시 확보한다.
- **기대 효과**: 블록 DCT의 보안 약점(패턴 추정 → 제거·위조)이 수치로 드러나면 "그림마다 키를 바꾸고 원장에 키 식별자를 기록"하는 설계 변경의 근거가 된다(Yang 외의 다중 키 완화는 임시책이라는 점도 함께 적기). 위조 실험은 젠룩의 "표시 의무" 맥락에서 "가짜 표시"의 실례가 된다.
- **실행 비용**: numpy만, 추가 모델 없음. 실험 2 결과 이미지가 저장돼 있다면 **1시간 이내**(추정).
- **위험**: 우리 질감 적응 세기 때문에 평균이 순수 패턴에 수렴하지 않아 n=34로는 제거가 약할 수 있음 → "n이 작아 약하다"도 결과다. 표본이 작아 비율은 거칠다(실험 2와 같은 한계).

### 2위 — 워터마크 추가: **Watermark Anything**(국소화 32비트, MIT) — 논문 그림 크롭 빈틈 겨냥
- **무엇을**: wam_mit.pth(378MB)를 받아 실험 7의 10장에 삽입하고 실험 7 공격 5종(JPEG 74·42, 크롭 0.8, FFDNet, SD-VAE)과 **크롭 0.4·0.6**(실험 2 크롭 단계)을 돌린다. 판정은 논문 기준(픽셀 7% 이상 검출 + 비트 일치).
- **왜(근거)**: 우리 최대 빈틈은 논문 그림 크롭(TrustMark 0.45, 블록 DCT 0.05; 실험 2)과 회전이다. Watermark Anything 논문 표 2a(COCO)는 **기하 변환 TPR 99.3%/비트 91.8%**로 같은 표에서 TrustMark 36.3%/71.4%와 대비되며, 영역별 메시지 설계상 잘라낸 조각에도 표식이 남는다. Video Seal 논문 표 4에서는 복합 공격 비트 정확도 Watermark Anything 0.55 vs TrustMark 0.51(영상) — 압도적이지는 않음.
- **기대 효과**: 크롭 빈틈이 메워지는지(그림에서 특히) 확인. 흰 배경 그림에서 학습형이 또 무너지는지도 함께 관찰(실험 2의 "콘텐츠 특성" 발견 재검증).
- **실행 비용**: 다운로드 378MB + torch 환경(이미 있음). CPU 속도 표기 없음 — 추출기 약 96M 파라미터로 장당 수 초 추정. 설치·시험 **2~3시간**(추정).
- **위험**: 저장소가 2026-08 보관(읽기 전용)이라 Python 3.11·최신 torch 호환 문제를 스스로 풀어야 함. 메모리(이전 OOM). 디노이저·VAE 결과는 예측 불가(Yang 외는 이 모델을 시험 안 함). **대안**: 같은 Meta 저장소의 Video Seal 이미지 모델(y_256b_img.pth 228MB, 256비트, MIT; 논문 표 6에 CPU 수치 있음)은 유지보수 중이라 설치가 더 쉬울 수 있으나, VideoMarkBench(arXiv:2505.21620)에서 **가우시안 잡음 σ=0.15에 FNR→1**로 잡음 계열에 약했다.

### 3위 — 공격 추가: **경량 압축형 재생성(CompressAI bmshj2018) + 반복("rinsing")**
- **무엇을**: Zhao 외·WAVES 공통 공격인 bmshj2018 VAE(품질 1~6)로 10장을 재생성해 TrustMark·블록 DCT 검출률을 재고, FFDNet을 2회·4회 반복(WAVES의 rinsing 개념)해 "디노이저 반복이 블록 DCT 잔존 20~60%를 지우는가"를 본다. 가능하면 SD-VAE 통과 전에 잠재에 작은 가우시안 잡음(Zhao의 σ 0.10 상당)을 더한 "확률적 재생성" 1단계를 추가.
- **왜(근거)**: 4.2절 — 우리 SD-VAE 공격은 잡음 없는 가장 약한 재생성이라 TrustMark 80%가 과대평가일 수 있다(VINE 표 1 TrustMark 9.22%/34.20%). bmshj2018은 Zhao(표·그림 4)와 WAVES(Regen-VAE)에 공통이라 **문헌 수치와 직접 비교**가 되고(WAVES StegaStamp Regen-VAE 1.000), 우리 결과를 리더보드 언어로 말할 수 있다.
- **실행 비용**: `pip install compressai`(BSD-3) — **Windows 휠 없음, 소스 빌드 필요 가능**(README는 Linux·macOS만 명시). 모델은 작아 CPU 수 초/장 추정(크기 확인 못 함). 반복 FFDNet은 기존 코드로 즉시(장당 3~8초×회수). 잠재 잡음 추가는 `AutoencoderKL` encode 뒤 한 줄. 총 **1~2시간**(설치가 되면).
- **위험**: compressai Windows 설치 실패 시 TAESD(MIT, 1.2M 파라미터, diffusers `AutoencoderTiny`)로 대체 가능하나 벤치마크 미등재라 비교 불가. SD-VAE 재로딩은 메모리 주의(512px, float32 유지).

### 보류(화요일 이후)
- **AudioSeal 시연**(MIT, `pip install audioseal`, 가중치 94MB): 젠룩이 음원도 다루므로 "10초 음성에 16비트 심고 잘라도 위치가 잡힌다"는 짧은 시연은 반나절이면 가능하나, 이번 과제 그림 실험과는 별개. 약점(고역통과 TPR 0.82/FPR 0.60, 코덱 압축)도 함께 보여 줄 것.
- **SynthID Text**(transformers 4.46+): 문서 표시 의무 맥락의 시연 후보. 소형 모델이면 CPU 가능하나 검출기 학습(1만 예시 권고)이 부담.
- 생성 과정 워터마크(Tree-Ring·Gaussian Shading·PRC)는 **연구실 그림에 적용 불가**(모델이 만든 그림에만)이고 CPU 역변환 비용이 커서 과제 범위 밖. 발표에서는 "제공자 측 기술"로 구분해 설명만.
