## 1. 원본과 특징점 정합 후 검출 (조사 03 추천 1, 최우선)

### 1.1 무엇을 — 왜

| 무엇을 | 왜 (근거) |
|---|---|
| 의심 이미지를 **원장에 있는 원본에 특징점으로 정합해 기하 변형을 되돌린 뒤**, 기존 `tools/wm_blockdct.py`의 `score()`와 TrustMark `decode()`를 그대로 돌린다 | 연구실은 원본을 갖고 있어 블라인드 검출이 필수가 아니다(조사 03 §5.2, Lin 외 2001 I절). 새 신호를 넣지 않아 화질 손실이 없고, 실험 6(블록 DCT 동기 탐색)이 실패한 원인인 배율 전수 탐색이 사라진다(개발일지 '실험 6 재설계 근거') |
| 특징점은 **SIFT**부터 | SyncSeal 논문 Table 3이 비교 기준으로 쓴 것이 SIFT이고, 원본을 아는 정합에서 모서리 오차 1.5~1.8px(뒤집기·10° 회전·크롭 0.7·원근 0.1)로 SyncSeal보다 정확했다[요약, 조사 03 §2.4]. OpenCV 5.0 설치판에 `cv2.SIFT_create`가 메인 모듈(features)에 들어 있어 추가 설치가 없다[확인: 설치판 docstring, 5.x 헤더 `modules/features/include/opencv2/features.hpp` 380~382행] |
| 변환 모델은 **아핀(6자유도) 우선, 호모그래피(8자유도)는 비교용** | 우리 크롭 공격(`tools/attacks.py` 50~52행)은 정사각형을 잘라 원래 가로×세로로 늘리므로 가로·세로 배율이 다른 **비등방 아핀**이다[확인]. 유사변환(`estimateAffinePartial2D`, 균일 배율)으로는 원리상 맞출 수 없다(조사 03 §3.4 ①). 회전 공격은 유사변환이지만 아핀이 이를 포함한다. 자유도가 적을수록 RANSAC가 적은 inlier로도 안정된다[추정] |
| 정합 목표 정밀도 **0.5px 이내**, 되돌린 이미지는 **원본과 같은 크기**로 만든다 | 블록 DCT는 8×8 격자에 정확히 맞아야 상관이 생기고, 0.5px 어긋나면 상관이 약 절반(조사 03 §3.1). 출력 크기를 원본과 같게 해야 블록 격자가 원본과 일치한다 |
| TrustMark는 되돌린 이미지를 **그대로** 넣는다 | TrustMark `decode()`는 내부에서 이미지 전체(종횡비 2 초과면 중앙 정사각)를 245×245로 bilinear 축소해 디코더에 넣는다[확인: trustmark 0.9.2 소스 `trustmark.py` 32~72행, 121행, 452행]. 따라서 TrustMark에는 격자 정렬이 아니라 "원본과 같은 프레임 안에 내용이 같은 위치에 있는 것"이 중요하다 |

### 1.2 설치·크기·라이선스

- **추가 설치 없음.** 필요한 것은 모두 설치된 `opencv 5.0`(Apache-2.0)과 numpy·PIL이다. 참고로 PyPI 최신은 `opencv-python-headless 5.0.0.93`[확인: `pip index versions`, 2026-11-13].
- OpenCV 5.0에서 calib3d 모듈이 3d·calib·stereo로 나뉘었지만 **파이썬 이름은 `cv2.findHomography`, `cv2.estimateAffine2D` 그대로**다[확인: 5.0.0 설치판에서 호출 가능; 모듈 분할 사실은 heise·OpenCV.org 발표 자료 [요약]]. 공식 문서 사이트(docs.opencv.org)는 이번 세션에서 403으로 열리지 않아, 기본값은 GitHub 소스 헤더로 확인했다.
- 기본값 [확인: `opencv/4.x/modules/calib3d/include/opencv2/calib3d.hpp` 842~845행, 3326~3329행, 3378~3381행; 5.0 설치판 docstring에서 같은 인자 목록 확인]:
  - `findHomography(src, dst, method=0, ransacReprojThreshold=3, mask, maxIters=2000, confidence=0.995)`; method에 `RANSAC`, `LMEDS`, `RHO`, 그리고 `USAC_MAGSAC` 등 USAC 상수가 5.0 설치판에 있다[확인].
  - `estimateAffine2D(from, to, inliers, method=RANSAC, ransacReprojThreshold=3, maxIters=2000, confidence=0.99, refineIters=10)` — RANSAC 뒤 Levenberg-Marquardt로 inlier만 써서 재정련(docstring).
  - `SIFT_create(nfeatures=0, nOctaveLayers=3, contrastThreshold=0.04, edgeThreshold=10, sigma=1.6, enable_precise_upscale=False)`.
  - 서브픽셀 정련용 `findTransformECC(template, input, warpMatrix, motionType, criteria, inputMask, gaussFiltSize=5)`와 `MOTION_AFFINE`·`MOTION_HOMOGRAPHY`가 5.0 설치판에 있다[확인: docstring].

### 1.3 절차와 최소 코드 (새 파일 `experiments/exp09_register_detect.py`로; 기존 파일 수정 없음)

```python
import cv2, numpy as np
from PIL import Image
cv2.setRNGSeed(0)                      # RANSAC 재현성
SIFT = cv2.SIFT_create()               # 기본값. 선 그림에서 점이 적으면 contrastThreshold=0.01 시도
BF = cv2.BFMatcher(cv2.NORM_L2)

def register(query_pil, orig_pil, model="affine"):
    """query를 orig 좌표계로 되돌린 이미지(원본 크기)와 유효 영역 마스크, 변환, inlier 수를 돌려준다."""
    q = cv2.cvtColor(np.asarray(query_pil.convert("RGB")), cv2.COLOR_RGB2GRAY)
    o = cv2.cvtColor(np.asarray(orig_pil.convert("RGB")), cv2.COLOR_RGB2GRAY)
    kq, dq = SIFT.detectAndCompute(q, None)
    ko, do = SIFT.detectAndCompute(o, None)
    if dq is None or do is None or len(kq) < 4 or len(ko) < 4:
        return None
    good = [m for m, n in (p for p in BF.knnMatch(dq, do, k=2) if len(p) == 2) if m.distance < 0.75 * n.distance]
    if len(good) < 4:
        return None
    src = np.float32([kq[m.queryIdx].pt for m in good]).reshape(-1, 1, 2)   # 질의 좌표
    dst = np.float32([ko[m.trainIdx].pt for m in good]).reshape(-1, 1, 2)   # 원본 좌표
    H_o, W_o = o.shape
    if model == "affine":
        A, inl = cv2.estimateAffine2D(src, dst, method=cv2.RANSAC, ransacReprojThreshold=3.0)
        if A is None: return None
        M = np.vstack([A, [0, 0, 1]])
    else:
        M, inl = cv2.findHomography(src, dst, cv2.RANSAC, 3.0)
        if M is None: return None
    rgb = np.asarray(query_pil.convert("RGB"))
    back = cv2.warpPerspective(rgb, M, (W_o, H_o), flags=cv2.INTER_CUBIC, borderMode=cv2.BORDER_CONSTANT)
    valid = cv2.warpPerspective(np.full(q.shape, 255, np.uint8), M, (W_o, H_o), flags=cv2.INTER_NEAREST) > 0
    return Image.fromarray(back), valid, M, int(inl.sum())
```

- **블록 DCT 점수는 유효 영역의 블록만** 써야 한다. `score()`는 이미지 전체의 (블록, 계수)를 합산하므로 빈 영역(검정)이 분모에 들어가 점수가 희석된다. 실험 스크립트 안에 `_blocks`·`_carrier`를 불러 쓰되, `valid` 마스크가 블록 전체를 덮는 블록만 골라 `z = Σ(C·s)/√Σ(C²)`를 다시 계산하는 함수를 둔다(`tools/wm_blockdct.py`는 고치지 않음). 유효 블록만 쓰면 z의 귀무 분포는 여전히 N(0,1)이므로 실험 2와 같은 문턱을 쓸 수 있다[추정 — 음성 대조군으로 확인].
- **TrustMark**: `tm.decode(back, MODE="text")`. 빈 영역은 검정으로 두면 된다(TrustMark는 크롭·크기 조절로 학습됨, 조사 03 §2.2). 회전 공격의 90° 모호성이 걱정되면 `decode(..., ROTATION=True)`가 0·90·180·270°를 차례로 시도한다[확인: 소스 401~420행].
- **정합 정밀도 측정**: 공격 변환은 `tools/attacks.py`에서 `seed`로 재현되므로 참 변환을 알 수 있다. 참 변환과 추정 `M`으로 원본 네 모서리를 사상한 평균 거리(px)를 기록한다 — SyncSeal Table 3과 같은 척도라 바로 대조된다.
- **서브픽셀 정련(선택)**: RANSAC+LM 결과를 초기값으로 `cv2.findTransformECC(o, q, warp, cv2.MOTION_AFFINE, (cv2.TERM_CRITERIA_EPS | cv2.TERM_CRITERIA_COUNT, 50, 1e-5), None, 5)`. 함정: ECC의 warp 방향 규약(OpenCV 예제는 결과를 `WARP_INVERSE_MAP`으로 적용)을 사전 시험 1장에서 확인한 뒤 쓸 것. 블록 DCT 점수가 ECC 전후로 얼마나 오르는지가 "0.5px 가설"의 직접 검증이 된다.

### 1.4 선·글자 위주 그림에서의 대안

실험 3에서 그림 크롭의 ORB 검출률이 0.13~0.18이었던 원인은 특징점 부족이 아니라 **형제 그림 오탐이 문턱을 올린 것**(조사 06 §5 추천 1, 다른 그림 쌍 inlier 최대 120 대 크롭 질의 중앙값 21). 이번 정합은 정답 원본을 아는 상태이므로 문턱 문제는 없고, 남는 위험은 (a) 글자·눈금 같은 반복 요소가 잘못된 짝을 만들어 RANSAC가 틀린 변환을 고르는 것, (b) 선이 가늘어 키포인트 자체가 적은 것이다.

| 대안 | 무엇을 | 왜 | 비용·함정 |
|---|---|---|---|
| A. 글자 영역 키포인트 제외 | 텍스트 검출로 글자 상자를 찾아 그 안의 키포인트를 매칭에서 뺀다 | Guan 외 2026(생의학 그림 중복 검출)이 CRAFT 글자 마스킹 + SIFT 검증을 썼다(조사 06 §2.3, 민감도 80.7%). 마스킹 효과의 ablation은 없음 | OpenCV `cv2.dnn`의 EAST는 모델 파일(약 90MB대, 정확한 크기 확인 못 함)을 따로 받아야 한다. 더 싼 대리법: 키포인트 크기(`kp.size`)가 작고 밀집한 군집을 제외 — 효과 미확인[추정] |
| B. 밀도 기반 정합(특징점 없이) | `findTransformECC`를 피라미드(1/4 → 1/2 → 1)로 돌려 아핀을 직접 맞춘다 | 선 그림은 에지가 뚜렷해 밝기 기반 정합이 잘 맞는 편[추정]. 키포인트가 0개여도 동작 | 초기값이 멀면(배율 1.4, 큰 회전) 수렴 안 함 → 특징점 결과를 초기값으로 쓰는 하이브리드가 현실적. 회전 45°는 ECC 단독으로 어렵다[추정] |
| C. 키포인트 수 늘리기 | `contrastThreshold`를 0.04 → 0.01~0.02로, 또는 1/2 축소본에서도 검출해 합친다 | 흰 배경·가는 선은 대비가 낮은 극값이 많아 기본 문턱에 걸러진다[추정] | 거짓 짝도 늘어 RANSAC 반복(`maxIters`)을 5000으로 올려야 할 수 있음 |
| D. 선 두께 정규화 후 SIFT | 이진화 → 거리 변환 또는 세선화로 선 두께를 1~2px로 맞춘 뒤 검출 | 특허 도면 검색 문헌이 SIFT가 선 두께·점선 변화에 약하다고 보고(조사 06 §2.5, Castorena 외 2019 [요약]). 크롭+확대는 선을 굵게 만든다 | 세선화는 OpenCV 메인에 없음(`ximgproc`는 contrib). 거리 변환 `cv2.distanceTransform`은 메인에 있다[일반 지식, 설치판 미확인] |
| E. 그림 종류별 보고 | 선 그림 / 히트맵·막대 / 사진 삽입을 나눠 정합 성공률·모서리 오차·검출률을 따로 보고 | 선 그림 매칭은 "open challenge"(DeepPatent, 조사 06 §2.5). 실패 조건을 밝히는 것이 발표에서 정직하다 | 비용 없음 |

**추천 순서:** 기본 SIFT로 그림 9장 사전 시험 → 실패한 그림만 C → A/B. 세 가지 다 실패하는 그림은 "선 그림은 원본 정합이 안 된다"는 결과로 보고한다.

### 1.6 함정 정리

1. 유사변환(`estimateAffinePartial2D`)을 쓰면 비등방 크롭을 원리상 못 맞춘다 → 아핀.
2. `warpPerspective`의 `dsize`는 **원본 크기** `(W_o, H_o)`. 질의 크기로 두면 블록 격자가 어긋난다.
3. 블록 DCT 점수에서 빈 영역 블록을 빼지 않으면 점수가 희석된다(1.3).
4. 보간(`INTER_LINEAR`/`INTER_CUBIC`)이 고주파를 깎아 블록 DCT 신호가 준다(조사 03 §5.2 위험). 두 보간을 모두 기록해 비교한다.
5. 오탐 기준선: 워터마크 없는 원본을 같은 공격·정합·검출 경로로 돌려 음성 점수 분포를 얻는다(실험 6의 방식). 정합 자체가 점수를 올리지 않는지 확인하는 대조군이다.
6. RANSAC는 무작위 → `cv2.setRNGSeed(0)`. 동일 입력 재실행 때 inlier 수가 바뀌면 결과 표가 흔들린다.
7. 발표에서는 "블라인드 워터마크"가 아니라 **"원본 대조(non-blind) 검출"**로 구분해 말한다(조사 03 §5.2).
8. 실험 3의 ORB 문턱(38) 문제는 이 실험과 별개다. "어느 원본인지 찾기"는 조각 해시·SSCD(2절)가 맡고, 이 실험은 "원본을 아는 상태의 정합"만 측정한다.

### 6.2 알고리즘(설치판 소스 기준) [확인]

`crop_resistant_hash(image, hash_func=dhash, limit_segments=None, segment_threshold=128, min_segment_size=500, segmentation_image_size=300)`

1. 회색조 변환 → **300×300으로 강제 축소**(종횡비 무시, 637~666행) → 가우시안 블러(PIL 기본 반경 2) → 중앙값 필터(기본 3×3).
2. **밝기 128 문턱**으로 '밝은 영역(hill)'과 '어두운 영역(valley)'을 나눈 뒤, 4-연결 영역 확장(flood fill)으로 연결된 영역을 찾는다(`_find_all_segments`, 589~634행). 밝은 영역을 먼저 모두 찾고, 그다음 어두운 영역을 찾는다.
3. 픽셀 수가 **500 초과**(300×300의 0.56%)인 영역만 남긴다. 영역이 하나도 없으면 이미지 전체를 한 영역으로 삼는다.
4. 각 영역의 **바운딩 박스**(원본 좌표로 되돌림)를 원본에서 잘라 `hash_func`(기본 dHash 64비트)를 계산한다. 영역 모양 자체는 쓰지 않고 박스만 쓴다(682~694행).
5. 결과는 `ImageMultiHash`(영역 해시 목록). 비교(`hash_diff`, 489~513행): 질의의 영역 해시마다 상대 해시 목록 중 **최소 해밍 거리**를 구하고, 그것이 `hamming_cutoff`(기본 = 비트 수 × `bit_error_rate` 0.25 = **16비트**) 이하면 '일치 영역'으로 센다. `matches(region_cutoff=1)`: **일치 영역이 1개 이상이면 같은 이미지**로 판정(514~525행). `__sub__`(거리)는 "영역 수 − 일치 수 + 평균거리 보정"이다.

**기본값의 근거:** 소스 주석은 `segment_threshold`에 대해 "정적으로 두어야 한다. 봉우리·골 사이에서 동적으로 정하면 매칭이 깨진다"고만 적고(658~659행), 128·500·300·0.25의 수치적 근거는 소스·README·이슈·PR 어디에도 없다(PR #120은 "최소 영역 크기를 올렸다"고만 함) [확인: 소스·README / 요약: 이슈·PR]. README의 예시는 `min_segment_size=500, segmentation_image_size=1000`을 쓴다[확인]. → **우리 실험 8에서 "라이브러리 기본값을 세트 그대로"라고 적는 것은 맞지만, 그 값이 논문 권장값인지는 말할 수 없다.**

**다른 알려진 함정 [확인, 소스 주석 653~654행]:** Pillow 6과 7 이상에서 회색조 변환 반올림이 달라 분할이 조금 달라진다 → 등록 쪽과 조회 쪽의 Pillow 버전을 같게 맞출 것.

### 6.3 흰 배경 그림에서 예상되는 약점 [추정 — 소스 구조에서 도출, 실험으로 확인할 것]

1. **배경이 한 덩어리가 된다.** 흰 배경(밝기 255 > 128)은 연결된 하나의 거대한 '밝은 영역'이 되고, 그 바운딩 박스는 사실상 **이미지 전체**다 → 이 영역의 dHash는 전체 해시와 같아져 크롭 저항력이 없다. 선·글자가 배경을 완전히 가르지 않으면(그래프 축이 액자처럼 닫혀 있지 않으면) 배경 영역은 하나다.
2. **선·글자는 영역이 안 된다.** 300×300으로 줄이고 블러·중앙값 필터를 거치면 1~2px 선과 작은 글자는 128 문턱을 넘지 못하거나 500px 미달로 버려진다. 남는 '어두운 영역'은 큼직한 색 블록(막대그래프의 막대, 히트맵의 어두운 칸, 사진 삽입부) 정도다 → 선 그림·도면은 영역이 0~2개로 전체 해시와 다를 바 없고, 히트맵·막대그래프는 영역이 생긴다. 우리 그림 9장 중 종류별로 영역 수를 먼저 세어 보는 것이 실험 8의 첫 확인 사항.
3. **형제 그림 오탐.** 같은 논문의 그림들은 같은 범례 상자·같은 축 영역을 재사용한다(실험 3의 ORB 형제 그림 발견과 같은 원리). `region_cutoff=1`이면 범례 상자 하나만 16비트 이내로 맞아도 "같은 이미지"가 된다 → 질의당 오탐이 실험 5의 조각 해시보다 높을 가능성이 크다. 실험 8처럼 **점수 = 일치 영역 수**로 두고 문턱을 음성 질의에서 정해야 한다.
4. **밝기 변화에 취약.** 문턱 128이 고정이라 밝기·대비 공격(WAVES 밝기 ×1.2~2)으로 중간 밝기 영역이 문턱을 넘나들면 영역 분할 자체가 바뀐다. 사진보다 중간 톤이 적은 그림은 영향이 작을 수도 있다(방향 불확실).
5. **종횡비 무시.** 300×300 강제 축소라 가로로 긴 그림(1600×700 등)은 가로 방향이 2배 더 눌린다. 크롭 뒤 종횡비가 달라지면 영역 모양이 달라지는데, 바운딩 박스를 원본 좌표로 되돌려 dHash를 계산하므로 박스 안 내용이 같으면 해시는 비슷하게 유지된다 — 영향은 작을 것으로 본다.

**실험 8에 넣을 보조 측정(비용 거의 없음):** 이미지마다 `len(h.segment_hashes)`를 기록해 "영역 수 ≤ 1인 그림 비율"을 보고한다. 이 비율이 높으면 위 1·2가 실제로 일어난 증거가 되고, 그림에서의 낮은 검출률을 설명한다.

### 6.4 최소 코드 (설치된 imagehash 그대로)

```python
import imagehash
from PIL import Image

ref = imagehash.crop_resistant_hash(Image.open("original.png"))      # 등록(기본값: dHash, 128, 500, 300)
qry = imagehash.crop_resistant_hash(Image.open("cropped.png"))
n_match, dist_sum = qry.hash_diff(ref)        # 일치 영역 수, 거리 합 (기본 bit_error_rate 0.25 → 16비트)
print(len(ref.segment_hashes), len(qry.segment_hashes), n_match, qry.matches(ref))
# 저장: str(ref) → imagehash.hex_to_multihash(s) 로 복원 (README 예시)
```

CPU 시간: 300×300 영역 확장이 순수 파이썬 set 연산이라 장당 수 초[추정]. 76장 × (원본 + 크롭 10종)이면 수 분~십수 분[추정, 조사 04의 추정과 같음]. 메모리는 무시할 수준.
