## 5. imagehash `crop_resistant_hash` — 원 논문·알고리즘·흰 배경 약점

(의뢰 순서와 달리 5번을 먼저 둔 이유: 이미 설치된 라이브러리의 소스를 직접 읽어 확정한 내용이라 가장 확실하고, 실험 8(개발일지 '실험 8 설계')에서 당장 쓰기 때문.)

### 5.2 알고리즘(설치판 소스 기준) [확인]

`crop_resistant_hash(image, hash_func=dhash, limit_segments=None, segment_threshold=128, min_segment_size=500, segmentation_image_size=300)`

1. 회색조 변환 → **300×300으로 강제 축소**(종횡비 무시, 637~666행) → 가우시안 블러(PIL 기본 반경 2) → 중앙값 필터(기본 3×3).
2. **밝기 128 문턱**으로 '밝은 영역(hill)'과 '어두운 영역(valley)'을 나눈 뒤, 4-연결 영역 확장(flood fill)으로 연결된 영역을 찾는다(`_find_all_segments`, 589~634행). 밝은 영역을 먼저 모두 찾고, 그다음 어두운 영역을 찾는다.
3. 픽셀 수가 **500 초과**(300×300의 0.56%)인 영역만 남긴다. 영역이 하나도 없으면 이미지 전체를 한 영역으로 삼는다.
4. 각 영역의 **바운딩 박스**(원본 좌표로 되돌림)를 원본에서 잘라 `hash_func`(기본 dHash 64비트)를 계산한다. 영역 모양 자체는 쓰지 않고 박스만 쓴다(682~694행).
5. 결과는 `ImageMultiHash`(영역 해시 목록). 비교(`hash_diff`, 489~513행): 질의의 영역 해시마다 상대 해시 목록 중 **최소 해밍 거리**를 구하고, 그것이 `hamming_cutoff`(기본 = 비트 수 × `bit_error_rate` 0.25 = **16비트**) 이하면 '일치 영역'으로 센다. `matches(region_cutoff=1)`: **일치 영역이 1개 이상이면 같은 이미지**로 판정(514~525행). `__sub__`(거리)는 "영역 수 − 일치 수 + 평균거리 보정"이다.

**기본값의 근거:** 소스 주석은 `segment_threshold`에 대해 "정적으로 두어야 한다. 봉우리·골 사이에서 동적으로 정하면 매칭이 깨진다"고만 적고(658~659행), 128·500·300·0.25의 수치적 근거는 소스·README·이슈·PR 어디에도 없다(PR #120은 "최소 영역 크기를 올렸다"고만 함) [확인: 소스·README / 요약: 이슈·PR]. README의 예시는 `min_segment_size=500, segmentation_image_size=1000`을 쓴다[확인]. → **우리 실험 8에서 "라이브러리 기본값을 세트 그대로"라고 적는 것은 맞지만, 그 값이 논문 권장값인지는 말할 수 없다.**

**다른 알려진 함정 [확인, 소스 주석 653~654행]:** Pillow 6과 7 이상에서 회색조 변환 반올림이 달라 분할이 조금 달라진다 → 등록 쪽과 조회 쪽의 Pillow 버전을 같게 맞출 것.

### 5.3 흰 배경 그림에서 예상되는 약점 [추정 — 소스 구조에서 도출, 실험으로 확인할 것]

1. **배경이 한 덩어리가 된다.** 흰 배경(밝기 255 > 128)은 연결된 하나의 거대한 '밝은 영역'이 되고, 그 바운딩 박스는 사실상 **이미지 전체**다 → 이 영역의 dHash는 전체 해시와 같아져 크롭 저항력이 없다. 선·글자가 배경을 완전히 가르지 않으면(그래프 축이 액자처럼 닫혀 있지 않으면) 배경 영역은 하나다.
2. **선·글자는 영역이 안 된다.** 300×300으로 줄이고 블러·중앙값 필터를 거치면 1~2px 선과 작은 글자는 128 문턱을 넘지 못하거나 500px 미달로 버려진다. 남는 '어두운 영역'은 큼직한 색 블록(막대그래프의 막대, 히트맵의 어두운 칸, 사진 삽입부) 정도다 → 선 그림·도면은 영역이 0~2개로 전체 해시와 다를 바 없고, 히트맵·막대그래프는 영역이 생긴다. 우리 그림 9장 중 종류별로 영역 수를 먼저 세어 보는 것이 실험 8의 첫 확인 사항.
3. **형제 그림 오탐.** 같은 논문의 그림들은 같은 범례 상자·같은 축 영역을 재사용한다(실험 3의 ORB 형제 그림 발견과 같은 원리). `region_cutoff=1`이면 범례 상자 하나만 16비트 이내로 맞아도 "같은 이미지"가 된다 → 질의당 오탐이 실험 5의 조각 해시보다 높을 가능성이 크다. 실험 8처럼 **점수 = 일치 영역 수**로 두고 문턱을 음성 질의에서 정해야 한다.
4. **밝기 변화에 취약.** 문턱 128이 고정이라 밝기·대비 공격(WAVES 밝기 ×1.2~2)으로 중간 밝기 영역이 문턱을 넘나들면 영역 분할 자체가 바뀐다. 사진보다 중간 톤이 적은 그림은 영향이 작을 수도 있다(방향 불확실).
5. **종횡비 무시.** 300×300 강제 축소라 가로로 긴 그림(1600×700 등)은 가로 방향이 2배 더 눌린다. 크롭 뒤 종횡비가 달라지면 영역 모양이 달라지는데, 바운딩 박스를 원본 좌표로 되돌려 dHash를 계산하므로 박스 안 내용이 같으면 해시는 비슷하게 유지된다 — 영향은 작을 것으로 본다.

**실험 8에 넣을 보조 측정(비용 거의 없음):** 이미지마다 `len(h.segment_hashes)`를 기록해 "영역 수 ≤ 1인 그림 비율"을 보고한다. 이 비율이 높으면 위 1·2가 실제로 일어난 증거가 되고, 그림에서의 낮은 검출률을 설명한다.

### 5.4 최소 코드 (설치된 imagehash 그대로)

```python
import imagehash
from PIL import Image

ref = imagehash.crop_resistant_hash(Image.open("original.png"))      # 등록(기본값: dHash, 128, 500, 300)
qry = imagehash.crop_resistant_hash(Image.open("cropped.png"))
n_match, dist_sum = qry.hash_diff(ref)        # 일치 영역 수, 거리 합 (기본 bit_error_rate 0.25 → 16비트)
print(len(ref.segment_hashes), len(qry.segment_hashes), n_match, qry.matches(ref))
# 저장: str(ref) → imagehash.hex_to_multihash(s) 로 복원 (README 예시)
```

CPU 시간: 300×300 영역 확장이 순수 파이썬 set 연산이라 장당 수 초[추정]. 76장 × (원본 + 크롭 10종)이면 수 분~십수 분[추정, 조사 04의 추정과 같음]. 메모리는 무시할 수준.
